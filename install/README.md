Install day is where MagnusBilling is worst, which makes it MEGATRON's best
adoption lever *and* its strongest security control

## The security promise, and how it is kept

> **There is no path through the wizard that produces an insecure install.**

That is a strong claim, so it is not left as a claim. The mechanism is that an
insecure install is **not expressible** — not "rejected", *unrepresentable*:

- **There is no password field. Anywhere. At any nesting level.** Credentials
  are generated by the wizard and written to a mode-`0600` secrets file. They
  are never an input. `additionalProperties: false` on every object means one
  cannot be added later by someone who wants one.

  This is the direct structural answer to Magnus's default `root`/`magnus`:
  you cannot ship a default password when the config file has nowhere to write
  one. It also has a benefit operators will actually feel — **the answers file
  contains no secrets, so it is safe to commit to their own config repo.**
  Reproducible installs stop being in tension with keeping keys out of git.

- **`admin.bind` is an enum of loopback forms**, so `0.0.0.0` cannot be typed.
- **SIP over UDP cannot be enabled without a non-empty trunk allowlist**, and
  `restrict_to_trunks` has no `false` case.
- **TLS is required**, not a checkbox — a spoofed-source flood cannot complete
  a TLS handshake, so connection-oriented SIP is structurally immune to that
  whole attack class.
- **The prepaid fail-direction has exactly one legal value** (`closed`), and
  the pair has no default at all, because §4.4 says this must never be chosen
  by accident.
- **The test call cannot be claimed without media.** Signalling-only success is
  one of the three money-losing failure modes the platform exists to design out.

[`ci/check_wizard_answers.py`](../ci/check_wizard_answers.py) proves it, by
attempting **18 insecure installs** — a password field, a pasted private key,
an admin console on `0.0.0.0`, open 5060, prepaid failing open — and asserting
the schema refuses every one. It also fails if that battery ever shrinks, since
the battery is the only thing standing behind the promise.

```sh
python ci/check_wizard_answers.py     # needs pyyaml + jsonschema
```

## The TUI masthead

Two widths. The wizard picks by terminal width: **wide at ≥ 60 columns, narrow
below.** Both are checked in CI ([`ci/policy_check.py`](../ci/policy_check.py),
rule group `INSTALLER-ASSETS`).

```
  .     .  .......  .......  .     .     .     .     .  .......  .     .
========================================================================
  CLASS-4 + CLASS-5 SWITCH  .  REALTIME BILLING  .  SHIELDS UP
```

The letters are extruded: `#` is the face, `.` is the shadow the solid
silhouette casts down and to the right. The shadow is cast by the **filled**
outline rather than by the strokes, so it never appears inside a letterform
where it would just read as noise at this size.

The narrow variant is deliberately **flat**, not a shrunken 3D. Below 60
columns an extrusion costs a column and a row it does not have, and the trade
at that size is legibility over flourish — a masthead that wraps has failed at
the only job it has.

**Pure 7-bit ASCII, deliberately.** No box-drawing characters, no em dashes, no
Unicode of any kind. This is the first thing an operator sees, and it is seen
in the least forgiving place a program ever renders: a fresh Debian box over
SSH, often with `LANG=C`, sometimes on a provider's serial console, sometimes
in a rescue shell. A masthead that arrives as `â??â??â??` says "this was
built by people who never tried it on a real server" before the operator has
read a single word. The check in CI enforces this rather than trusting it.

Width is capped at **78 columns** so it never wraps in an 80-column terminal —
a wrapped banner looks worse than no banner.

### Colour

The TUI takes its colours from [`ui/tokens.css`](../ui/tokens.css), which is the
single source of truth for the console, the portal *and* the installer. The same
rule applies here as on screen: **the chrome is monochrome ink, and the only
saturated colour is state.** The banner is ink, not accent — it is a masthead,
not a status.

| Token | 256-colour fallback | Used for |
|---|---|---|
| `--mg-ink` | 255 / 232 | banner, headings, answers |
| `--mg-ink-muted` | 245 | prompts, help text |
| `--mg-good` | 29 | a check that passed |
| `--mg-warning` | 136 | a check that passed with a caveat |
| `--mg-critical` | 160 | a check that failed |

Degrade in this order: 24-bit → 256-colour → 16-colour → **no colour at all**.
The last one is not a courtesy. Preflight output is the part of this program
most likely to be pasted into a support ticket or piped through `tee`, so every
status carries a word and a glyph beside it and never rides on colour alone:

```
  [ ok ]  public IPv4 reachable from outside      203.0.113.10
  [ ok ]  5061/tcp reachable from outside
  [warn]  5060/udp reachable from outside         restricted to 2 trunks
  [FAIL]  RTP 16384-32768/udp not reachable
          -> your provider firewall is dropping it. Open the range, or
             set network.behind_nat and supply the public address.
```

That last block is the whole design in miniature: **report what is wrong and
how to fix it.** A switch behind a NAT or firewall nobody checked is the
single biggest source of "it doesn't work" in this industry, and an operator
who is told only that something failed will open a support ticket.

## Status

Nothing here is implemented. The Go installer does not exist
([#5](https://github.com/XYZTheo/MEGATRON/issues/5)) and cannot be built on the
machine this was written on — there is no Go toolchain, and no MEGATRON
component has yet run on Linux ([#2](https://github.com/XYZTheo/MEGATRON/issues/2)).

What exists is the contract the installer must satisfy, the example it must
accept, the masthead it must render, and the checks that hold all three to
their claims. That ordering is deliberate: it is the same one used for the
[shield telemetry contract](../contracts/shield-telemetry.openapi.yaml), and it
means the implementation gets written against a specification rather than the
specification getting reverse-engineered from whatever the implementation did.
